# Rebuild D-PoDL around validator-verified useful work

The AIBC repository wires up the vocabulary of Distributed Proof-of-Deep-Learning but none of the parts that make it secure. Every value the contracts check is self-reported. A fresh account with no training and no IPFS content can mint the 100-DPDL block reward. A single transaction can permanently halt block production. Ray launches N training processes but never synchronizes a gradient. None of that is fatal, because between the last code commit (September 2025) and November 2026 the field built most of what the project lacks. Templar's Covenant-72B showed that validator-measured loss scoring (Gauntlet) can incentivize permissionless pre-training at 72B parameters. Gensyn's Verde and the 2026 OVIG preprint turned optimistic replay-and-bisection verification into concrete designs. TOPLOC made inference checks nearly free. SparseLoCo and the DiLoCo family took internet bandwidth off the list of blockers. Prime Intellect's frozen-verifier NanoGPT study showed that coding agents can do measurable training-recipe research under a cheat-resistant harness. The big step forward is not a better trainer but a change in what "proof of deep learning" means: instead of training a random model to mint a block, a miner submits an improvement to a shared, frozen training recipe or base model, validators re-measure it, and an existing L2 settles it with a challenge window and slashing. Keep the paper's hash-binding and model-referencing ideas, the safetensors-plus-signed-manifest pattern, the token contract and the dev stack. Replace the toy model, Hash-to-Architecture, Ray orchestration, self-verification and all three protocol contracts with modded-nanogpt or nanochat, torchft or a DiLoCo outer loop, Gauntlet-style scoring, toploc, and a commit/challenge/settle contract. The strongest niche is an open, rigorously threat-modelled reference implementation of verifiable useful-work training, with a "verifiable autoresearch" task as its flagship: humans or AI agents submit recipe diffs that a frozen multi-seed verifier scores. Ship it as a research testnet or subnet, not as a new token.

## The prototype mints 100 DPDL for zero work

In practice the system is N self-scoring trainers plus an off-chain operator who promotes the best self-reported result. Ray's `TorchTrainer` starts N copies of a worker loop. Each copy runs a deterministic nonce search and trains a small text classifier on AG News. It then evaluates itself, uploads safetensors plus an EIP-712-signed manifest to a local IPFS daemon, and submits a model transaction (MTX) to a permissionless on-chain list. After training, one operator key reads each submitter's own `accuracy_bps` out of their manifest, sorts by it, logs it as "True Accuracy", and promotes the winner to reference model on chain ([trainer.py:278-411](../dpodl_core/trainer.py)). The block path is effectively dead. The worker calls `submit_block` with keyword arguments that don't exist in the function signature and passes no signer key, so the resulting `TypeError` is swallowed by a bare `except` ([worker.py:732-749](../dpodl_core/worker.py); [blockchain_interface.py:432-440](../dpodl_core/blockchain_interface.py)). `TaskRegistry` is not referenced by any Python module or contract ([TaskRegistry.sol](../blockchain/contracts/TaskRegistry.sol)).

**Nothing about training is verified by anyone other than the worker that did it.** `ModelRegistry.submitBlock` takes `_postHash` as a caller-supplied integer and compares it against a threshold of about 2^256 − 2^24. It never sees a nonce, a previous block or a model hash. Its `_accuracyBPS` check has a lower bound but no upper bound ([ModelRegistry.sol:295-334](../blockchain/contracts/ModelRegistry.sol); [helper-hardhat-config.js:8-34](../blockchain/helper-hardhat-config.js)). The code review that produced this report ran scratch proof-of-concept tests, kept outside the repo, that confirmed four failures:

- **Free minting.** `submitBlock("fake","fakeD",10000,150,0,"QmGD")` from a fresh account earns the full block reward.
- **One-transaction halt.** Submitting `accuracyBPS = 2^256−1` makes the next honest block revert on an overflow in the improvement check (`ModelRegistry.sol:272`).
- **MTX/block brick.** One MTX promotion makes `submitBlock` revert forever, because the promoted CID is missing from block history (`:258-266, 474-475`).
- **Finite lifetime.** Steps must rise by 50 per block under a 10,000 cap, so the chain dies after about 198 blocks.

On the Python side, `verify_proof_of_training_consistency` only recomputes hashes from values inside the same dictionary, so a fabricated state with random Merkle leaves and `accuracy = 0.99` returns `True` ([verification.py:131-323](../dpodl_core/verification.py)). The shipped T2 threshold of 2^256 accepts every hash ([config_utils.py:25](../dpodl_core/config_utils.py)). The manifest signature covers `structured_data` but not the `files` section that is actually downloaded and hash-checked, so swapping in an attacker's model CID still verifies ([ipfs_utils.py:559-622](../dpodl_core/ipfs_utils.py)). Miners also evaluate themselves on the public AG News **test** split ([data_loader.py:94-95](../dpodl_core/data_loader.py)). That inverts the D-PoDL design, where task publishers keep test data private and miners "are given only training datasets" ([D-PoDL paper, Su, Larangeira & Tanaka, `Research_papers/579857605/579857605.md:142,162`](../Research_papers/579857605/579857605.md)).

The "distributed" part is not distributed either. Nothing in `dpodl_core/` or `scripts/` calls `prepare_model`, `DistributedDataParallel` or `all_reduce`. Each rank trains a full private copy on a contiguous 1/N shard and signs its own MTX ([worker.py:247, 324-331, 847-853](../dpodl_core/worker.py)). Every rank starts from the same hard-coded `prev_block_hash = "0x1111"` and the same nonce search from zero, so every rank, and every run, lands on the same nonce and the same architecture ([config_utils.py:27](../dpodl_core/config_utils.py); [worker.py:277-285](../dpodl_core/worker.py)).

| D-PoDL paper element (`579857605.md`) | What the code does | Status |
|---|---|---|
| PreHash(prevBK, refM, nonce) ≤ T1, bound to the previous block (`:96`) | `prevBK` is a static config string; the chain never checks T1 | Not bound to chain state, no precomputation resistance |
| HtoA → architecture, hyper-parameters, seed (`:96`) | Picks from about 2.6k grid points; activation and dropout are ignored; the seed is applied after the model is built ([crypto.py:225-288](../dpodl_core/crypto.py); [models.py](../dpodl_core/models.py)) | Partial and buggy |
| initM from a referenced model (`:96,116`) | The worker reads a config key the trainer never sets; `transfer_reference_weights` is undefined ([worker.py:256-381](../dpodl_core/worker.py)) | Never runs; every model trains from scratch |
| Verify via Merkle spot-checks of checkpoints (`:101-104,124`) | Self-consistency check only; Merkle proof helpers are never called | Missing |
| Step-proportional, recursive reference rewards (`:178`) | Fixed 20% to the one directly referenced block; flat MTX reward chosen by the owner ([ModelRegistry.sol:406-487](../blockchain/contracts/ModelRegistry.sol)) | Deviates |
| Publisher-held test sets across time slots (`:142,162`) | `TaskRegistry` stores free-text strings and an unescrowed reward number | Missing |

The engineering state matches the protocol state. `npm ci` fails on a stale lockfile: it pins OZ 5.0.2 while `package.json` asks for `^5.3.0`. After `npm install`, the 71 Hardhat happy-path tests pass. Six of the seven Python test files are empty, and bare `pytest`, which is what CI runs, fails at collection ([blockchain/package.json:21](../blockchain/package.json); [.github/workflows/main.yml](../.github/workflows/main.yml)). Only about 4.6k lines of Python and 1.15k of Solidity do real work. `requirements.txt` pulls in TensorFlow and DeepSpeed, which nothing imports, and `web3>=6.0.0` is wrong for code that needs v7+ middleware ([requirements.txt](../requirements.txt); [blockchain_interface.py:8](../dpodl_core/blockchain_interface.py)). The docs say the project "has successfully implemented the core mechanics of the D-PoDL framework" ([docs/StateOfTheArt.md:78](../docs/StateOfTheArt.md)). The README still points to Polygon Mumbai, which has been retired ([README.md:120](../README.md); [Alchemy](https://alchemy.com/blog/polygon-amoy-is-live)). Two things soften this verdict. The paper itself treats "M is trained correctly from initM" as a black box behind Merkle spot-checks, so the code skipped exactly the part the paper left abstract. And the plumbing works: the safetensors manifest, the EIP-1559 transaction helper, the role-based mint and the one-command dev stack can all be reused.

## Bandwidth stopped being the bottleneck in 2026

The algorithmic question that justified Ray-style cluster training, "can you train over the internet at all?", is settled. Google's DiLoCo scaling-law work found DiLoCo outperforming data-parallel training at 10B parameters with more than 100x less communication ([arXiv 2503.09799](https://arxiv.org/abs/2503.09799)). Streaming DiLoCo matched tuned data-parallel training on a 1B model with two orders of magnitude less bandwidth ([arXiv 2501.18512](https://arxiv.org/abs/2501.18512)). SparseLoCo combines Top-k sparsification, 2-bit quantization and error feedback, and outperformed both DiLoCo and DeMo at 178M–2B ([arXiv 2508.15706](https://arxiv.org/abs/2508.15706)). MuLoCo uses Muon as the inner optimizer and communicates 8x less than DiLoCo ([arXiv 2505.23725](https://arxiv.org/html/2505.23725v2)). DeMo reached ICLR 2026 with up to 85x less data per GPU than AdamW-DDP ([ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/17790fc9b4828206f99a0dea35da3657-Abstract-Conference.html)). In April 2026, DeepMind's **Decoupled DiLoCo** removed the lock-step barrier. Independent learners push parameter fragments asynchronously to a synchronizer that merges whatever arrives within a quorum and grace window, weighted by tokens ([arXiv 2604.21428](https://arxiv.org/abs/2604.21428)). Secondary coverage reports 88% goodput versus 27% for data-parallel under heavy simulated failures ([MarkTechPost via search](https://www.marktechpost.com/2026/04/23/google-deepmind-introduces-decoupled-diloco-an-asynchronous-training-architecture-achieving-88-goodput-under-high-hardware-failure-rates/)). That quorum-and-deadline merge is structurally a block: accept the contributions that arrive by the cutoff, weight them, and publish the new state. It assumes honest learners, though, and honest learners are exactly what D-PoDL cannot assume.

Two 2026 runs show what this looks like with real incentives. **Covenant-72B** (Templar, Bittensor SN3) trained a 72.7B dense model on about 1.1T tokens, with at least 70 permissionless peers. Each peer uploaded at only 110 Mb/s, and SparseLoCo compressed traffic by more than 146x. Each 20-minute round needed about 70 s of communication, for 94.5% compute utilization. The model reached 67.1 zero-shot MMLU against LLaMA-2-70B's 65.6 ([arXiv 2603.08163](https://arxiv.org/html/2603.08163v2)). Each peer also ran **at least 8×B200**, so "permissionless" here means permissionless for well-capitalized operators. Pluralis's **Agora** run trained an 8.6B model on 500B tokens over 40 days. Its 330 mostly consumer-GPU nodes each held one pipeline stage, and the run reached 63% of a centralized H100 baseline's token efficiency ([arXiv 2607.13332](https://arxiv.org/abs/2607.13332)). For post-training the barrier is lower still. In July 2026, 14 Macs on home internet generated all rollouts for an 8.3B MoE and kept one B200 trainer saturated. Weight deltas were compressed to a median 82 MB against a 9 GB checkpoint, and held-out pass@1 rose from 29% to 63% ([Pluralis blog](https://pluralis.ai/blog/rl-post-training-on-macs/); [Stoa](https://github.com/PluralisResearch/stoa)).

The same year also exposed how fragile these networks are as businesses. Templar's README now says its training protocol "is not currently active" ([one-covenant/templar](https://github.com/one-covenant/templar)). Covenant publicly left Bittensor in April 2026, though secondary accounts of what followed conflict ([FalconX](https://www.falconx.io/newsroom/state-of-bittensor-subnet-adoption-trends-network-mechanics-and-covenants-departure); [BlockEden](https://blockeden.xyz/blog/2026/04/22/bittensor-sn3-teutonic-1-trillion-parameter-decentralized-llm-training-may-2026/)). Gensyn lists RL Swarm as legacy with "no official swarms running" ([Gensyn docs](https://docs.gensyn.ai/)). Prime Intellect archived its p2p protocol repository on 2026-01-27 ([GitHub](https://github.com/PrimeIntellect-ai/protocol)), trained INTELLECT-3 on a centralized 512×H200 cluster ([arXiv 2512.16144](https://arxiv.org/abs/2512.16144v1)), and raised $130M to sell enterprise RL tooling ([TechCrunch](https://techcrunch.com/2026/07/08/prime-intellect-raises-130m-series-a-to-help-enterprises-build-their-own-ai-agents/)). Epoch AI estimates that decentralized training compute is growing about 20x a year but remains about 1,000x below the frontier ([Epoch AI](https://epoch.ai/gradient-updates/how-far-can-decentralized-training-over-the-internet-scale)). The binding constraints are now verification, Sybil resistance and token economics, and those are D-PoDL's home turf.

The tooling has shifted to match. **torchft** (now under meta-pytorch) shipped 0.3.1 on 2026-11-03 with fault-tolerant DDP/HSDP, a Lighthouse quorum server, and experimental LocalSGD/DiLoCo/Streaming DiLoCo. It is BSD-3 licensed and designed for datacenters, not untrusted WAN peers ([PyPI](https://pypi.org/project/torchft/); [GitHub](https://github.com/meta-pytorch/torchft)). Prime Intellect's WAN-oriented PCCL has had no release since May 2025 ([PyPI pypccl](https://pypi.org/project/pypccl/)). Hivemind is in maintenance ([PyPI](https://pypi.org/project/hivemind/)), and Petals has not released since 2023 ([PyPI](https://pypi.org/project/petals/)). Both Covenant and Pluralis exchanged pseudo-gradients and deltas through Cloudflare R2 object storage over HTTPS instead of live P2P all-reduce ([arXiv 2603.08163](https://arxiv.org/html/2603.08163v2); [Pluralis](https://pluralis.ai/blog/rl-post-training-on-macs/)). That validates D-PoDL's choice of a store-and-commit architecture, even though IPFS has no comparable large-run track record. Ray Train DDP on a LAN is simply the wrong primitive. Within one miner, ordinary DDP/FSDP is enough. Across miners, the exchange should be compressed pseudo-gradients or deltas written to storage and committed on chain.

## Re-measuring work beats proving it for untrusted training

The repo's documentation names zkDL as the future verification path ([docs/StateOfTheArt.md:80-84](../docs/StateOfTheArt.md); [zkDL, `Research_papers/2023-1174/2023-1174.md`](../Research_papers/2023-1174/2023-1174.md)). In 2026 that path is a dead end for useful models. zkDL proves a batch update in under a second, but only for a 10M-parameter network ([arXiv 2307.16273](https://arxiv.org/pdf/2307.16273)), and its authors say zkLLM's tlookup has superseded its ReLU technique ([zkDL project page](https://cs.uwaterloo.ca/~h299sun/project/zkdl)). Kaizen's recursive zkPoT also stops around VGG-11 at 10M parameters ([ePrint 2024/162](https://ia.cr/2024/162)). Proving *inference*, never mind training, still costs about 1,100x vLLM for an 8B model in the most careful 2026 measurement, and literature estimates run from 10^4x to 5×10^5x ([aisafety.sg research note](https://www.aisafety.sg/research/what-proving-llm-inference-actually-costs-research-note)). Plain Merkle-logged proof-of-learning is no better on its own. Fang et al. showed reproducible spoofing attacks that cost far less than honest training ([arXiv 2208.03567](https://arxiv.org/abs/2208.03567v2)). D-PoDL's checkpoint Merkle roots are the commitment half of a scheme whose verification half does not exist yet.

The 2025–26 literature fills that gap with **optimistic verification**. **Verde** has trainers commit checkpoint hashes, bisects a dispute N-ways down to one training step, then descends to a single operator. Re-execution costs under 6% at N=20 and under 1.1% at N=100, and total overhead is claimed under 10x, against about 10^4x for cryptographic proofs ([arXiv 2502.19405](https://arxiv.org/html/2502.19405)). Its limits matter for a small team. It needs bitwise reproducibility from RepOps kernels, which add **+58% to +374%** in training depending on model and GPU. It is FP32 and single-GPU only. It has no incentive layer. And the referee cannot run on the EVM, which has no floating point. Gensyn's public REE runtime (v0.8.0, 2026-10-05) does reproducible *inference* only, and its operator binaries are proprietary ([gensyn-ai/ree](https://github.com/gensyn-ai/ree)). Two alternatives avoid that dependency. Srivastava, Arora and Boneh log rounding decisions to get exact FP32 replication across A40, Titan XP and RTX 2080 Ti for GPT-2 117M and ResNet-50, with public code. That size range is exactly what a revived testnet would train ([arXiv 2403.09603](https://arxiv.org/html/2403.09603v3)). **OVIG** (June/September 2026) drops bitwise determinism entirely. It flags gradient differences beyond a boundary calibrated from honest replays on heterogeneous hardware, and reports **0% attack success at +14.3% compute** and a 1996x storage cut on Qwen3, though it is a preprint with no code ([arXiv 2606.21045](https://arxiv.org/abs/2606.21045)).

What actually shipped at scale is cheaper still: statistical re-measurement. Templar's **Gauntlet** validator applies each miner's pseudo-gradient and measures the loss change itself (LossScore). It gives a negative score to a peer whose update helps more on random data than on its assigned data, which catches copying. It normalizes updates to the median norm and smooths scores with OpenSkill ratings. That mechanism, MIT-licensed, pre-trained Covenant-72B ([arXiv 2603.08163](https://arxiv.org/html/2603.08163v2); [Gauntlet arXiv 2505.21684](https://arxiv.org/pdf/2505.21684)). It measures whether an update is useful, not whether specific computation happened, so it pairs naturally with D-PoDL's commitments. For anything involving inference, such as evaluation outputs or RL rollouts, **TOPLOC** fingerprints top-k activations in about 258 bytes per 32 tokens, tolerates GPU and kernel differences, and installs from pip under MIT ([arXiv 2501.16007](https://arxiv.org/abs/2501.16007); [toploc](https://github.com/PrimeIntellect-ai/toploc)). Bitwise-deterministic inference is also available on a pinned stack, at about 34% slowdown in SGLang ([LMSYS](https://www.lmsys.org/blog/2025-09-22-sglang-deterministic/)). TEEs are the trap. **TEE.fail** uses a DDR5 interposer costing under $1,000 to forge TDX quotes that pass Intel DCAP at "UpToDate". It also shows that NVIDIA GPU attestation can be relayed from another machine, and neither vendor treats physical interposers as in scope ([tee.fail](https://tee.fail/)). A permissionless miner controls its own hardware, so attestation can raise the cost of cheating but cannot be the guarantee.

| Approach | Verifies training? | Sourced overhead | Determinism needed | Mergeable OSS (Nov 2026) |
|---|---|---|---|---|
| Current D-PoDL (self-report + Merkle) | No | ~0 | No | — |
| Gauntlet LossScore re-measurement | Usefulness of the update | One eval per miner | No | Templar, MIT (protocol dormant) |
| Verde bisection | Exact step | <10x total; RepOps +58–374% | Bitwise | REE: MIT SDK, proprietary binaries, inference only |
| Rounding-log replay (Srivastava) | Exact step | Small storage; ≤117M tested | Achieved across GPUs | Public research code |
| OVIG calibrated replay | Step, within tolerance | +14.3% compute | No | None yet |
| TOPLOC | Inference and rollouts only | ~258 B / 32 tokens | No | toploc, MIT |
| zkML / ZK proof of training | Yes | 10^3–10^5x; training ≤10M params | No | EZKL (Trail of Bits-audited), JOLT Atlas; DeepProve under a custom licence |
| GPU TEE | Attests environment | ~3–7% (vendor claims) | No | Broken by physical interposers |

The design that follows has four layers and needs no new cryptography. Miners commit per-k-step checkpoint Merkle roots, beacon-derived data seeds and update hashes, and post stake. Validators recompute loss and accuracy from committed weights on assigned and held-out data, so nobody trusts a self-report. A challenge window allows N-ary bisection over the committed roots down to one step. A referee committee then replays that step on a pinned GPU and container, Srivastava-style for small models or OVIG-style once code exists, and a mismatch triggers slashing. Optional extras: TOPLOC for inference outputs, TEE attestation for referees only, and EZKL or JOLT Atlas proofs of a single disputed operator or a small-model evaluation. JOLT Atlas proves GPT-2 125M inference in about 15 s on a MacBook M3 ([arXiv 2602.17452](https://arxiv.org/html/2602.17452); [jolt-atlas](https://github.com/ICME-Lab/jolt-atlas)). Proof-of-learning with incentive security supplies the formal framing: the goal is to make cheating unprofitable, not impossible ([arXiv 2404.09005](https://arxiv.org/html/2404.09005v7)).

## Frozen verifiers turn PoDL into measurable research

The most valuable discovery for this project comes from outside crypto. In March 2026 Karpathy's **autoresearch** popularized a loop in which an agent edits `train.py`, runs a five-minute job, and keeps or reverts the change on a metric. It drew 66k+ stars in a month. One run of 700 experiments over two days found 20 improvements, worth an 11% speedup when transferred to a larger model ([Fortune](https://fortune.com/2026/03/17/andrej-karpathy-loop-autonomous-ai-agents-future/)). In August 2026 Prime Intellect turned the loop into a measured, adversarially hardened benchmark. Agents had to get a 124M GPT to validation loss 3.28 in the fewest steps, against a verified baseline of 3,290 steps and a human record of 2,600. A claim counted only if the mean of 8 runs on fixed seeds the agent could not change beat 3.27859 under a frozen `verify.py`. Those rules were added after agents gamed sample counts and killed runs early. Fable 5 running in claude-code reached 2,726 steps, closing 81.7% of the gap. Agents mostly stacked and tuned known methods rather than inventing new ones. Identical runs varied by about 54 steps from GPU nondeterminism alone ([Prime Intellect](https://primeintellect.ai/blog/measuring-autonomous-research); [frontier-automated-speedrun](https://github.com/PrimeIntellect-ai/frontier-automated-speedrun)).

**This is close to a ready-made spec for D-PoDL's missing Verify algorithm.** A task publisher posts a frozen recipe, a verifier and a seed schedule. Miners, human or agent, submit a diff plus a claimed score. Validators re-run k seeds and accept only statistically significant improvements. "Model referencing" becomes "build on the current best diff", the way speedrun records stack, and the paper's step-proportional, recursive reference reward ([`579857605.md:178`](../Research_papers/579857605/579857605.md)) becomes a royalty paid to every earlier diff that a new record includes. The 54-step noise floor shows why acceptance must use multi-seed confidence intervals rather than D-PoDL's single accuracy threshold. The agent finding also says what to pay for: transferable stacking rather than novelty. The searches did not find any 2026 project paying crypto incentives for autoresearch-style diffs, which leaves that niche open.

The base for such tasks is already a community standard. The modded-nanogpt wall-clock record fell from 114 s at the end of 2025 to **about 40 s by August 2026** ([Epoch AI](https://epoch.ai/data/nanogpt-speedrun-record-time); [modded-nanogpt](https://github.com/KellerJordan/modded-nanogpt)). nanochat packages tokenizer-to-chat-UI training, and its d26 tier slightly beats GPT-2 for about $300 ([nanochat](https://github.com/karpathy/nanochat); [gu-log](https://gu-log.vercel.app/en/posts/en-clawd-picks-20260208-karpathy-nanochat-gpt2)). Either replaces the bespoke `DeeperTransformer`, which has no positional encoding, mean-pools over padding tokens and tops out near 31M parameters, mostly embeddings ([models.py](../dpodl_core/models.py)). Muon is mainstream enough to be in Megatron Core ([NVIDIA via MEXC](https://www.mexc.com/news/1047932)), though a NeurIPS 2026 poster finds its gains over AdamW "mixed, schedule-sensitive" ([NeurIPS 2026](https://neurips.cc/virtual/2026/poster/155813)). That is one more reason to score against measured baselines rather than assume an optimizer.

Hash-to-Architecture needs re-scoping, not deletion. µP and its successors, CompleteP and Apple's ICLR 2026 "completed" transfer across width, depth, batch and duration, favor one parameterized model family whose hyperparameters transfer and whose loss follows scaling laws ([arXiv 2203.03466](https://arxiv.org/abs/2203.03466); [arXiv 2505.01618](https://arxiv.org/html/2505.01618v3); [arXiv 2512.22382](https://arxiv.org/abs/2512.22382v1)). Drawing architectures at random from a hash wastes miner compute off the efficient frontier, and it breaks weight-space merging, which needs a shared trunk. The paper's actual purpose for the hash is unpredictable, miner-specific work that resists precomputation and copying. A beacon-derived hash can still deliver that if it chooses a µP grid point, a data-order seed and an assigned data shard. The assigned shard is exactly what Gauntlet's assigned-versus-random anti-copy test needs. Validators can then score a submission against its scaling-law-predicted loss rather than raw accuracy.

Modular training gives MTX a second, merge-friendly meaning. Ai2's FlexOlmo has data owners train expert modules against a shared public model, and owners can switch their contributions on or off ([arXiv 2507.07024](https://arxiv.org/html/2507.07024v4)). FlexMoRE, from July 2026, replaces most full experts with low-rank adapters and beats the full-expert baseline with under a third of the parameters ([Ai2 blog](https://allenai.org/blog/flexmore)). Together with Branch-Train-MiX ([arXiv 2403.07816](https://arxiv.org/abs/2403.07816)) and TIES/DARE merging in MergeKit ([mergekit](https://github.com/arcee-ai/mergekit)), these let a referenced-model contribution be a small adapter against a known base hash. Validators can cheaply re-apply and re-evaluate it, and the protocol can test whether a merge of the top-k beats every parent, then pay the parents.

The evaluation design has to assume contamination. A mid-2026 audit found that three contamination detectors solved only 60% of challenges, and concluded that provenance has to replace detection ([arXiv 2606.03305](https://arxiv.org/pdf/2606.03305)). Macrocosmos's SN37 delays picking up submissions so that foreknowledge of the test cannot be exploited ([SN37 docs](https://docs.macrocosmos.ai/subnet-37-finetuning/subnet-37-incentive-mechanism)), and Nous's finetuning subnet timestamps model hashes on chain before evaluation ([finetuning-subnet](https://github.com/NousResearch/finetuning-subnet)). The publisher should commit to a hash of a secret pool and require model commitments before reveal. Each round should evaluate on a slice drawn with a post-deadline block hash, from FineWeb-Edu or DCLM-class data ([arXiv 2406.17557](https://arxiv.org/abs/2406.17557); [arXiv 2406.11794](https://arxiv.org/abs/2406.11794)) or freshly generated verifier-backed tasks of the kind behind SYNTHETIC-2 ([Prime Intellect](https://primeintellect.ai/blog/synthetic-2-release)).

## Training-as-consensus is a weak bet in 2026

The field is skeptical of the paper's central bet, that training can replace hashing as the block-production mechanism. The 2025 SoK "Is Proof-of-Useful-Work Really Useful?" reviews more than 50 constructions. It concludes that economic utility does not add to a chain's security budget, and recommends verifiable computation, partial incentive allocation and utility-aware difficulty ([ePrint 2025/1814](https://eprint.iacr.org/2025/1814)). A June 2026 paper calls a formal security game for ML-work consensus "an open research problem" ([arXiv 2606.24942](https://arxiv.org/abs/2606.24942)). The closest recent peers to D-PoDL's pre-hash design are SEDULity, which encodes the template block into training ([arXiv 2512.13666](https://arxiv.org/abs/2512.13666)), and a near-namesake 2025 IET paper on "Proof of Distributed Deep Learning Work" ([Wiley](https://ietresearch.onlinelibrary.wiley.com/doi/10.1049/sfw2/3378383)). None of the live systems that pay for training uses it as consensus. Templar SN3, IOTA SN9 (which opened consumer "Train at Home" on 2026-02-10) and Gradients SN56 all run on a PoS chain and reward training as an application through validator scoring ([Macrocosmos](https://macrocosmosai.substack.com/p/welcome-to-train-at-home); [taooutsider](https://www.taooutsider.com/blog/machine-learning-on-bittensor-training-inference-evaluation/)). The useful-work L1s are not encouraging either. Ambient's proof of logits verifies inference, not training, and is unaudited ([Ambient docs](https://ambient.xyz/docs/learn/proof-of-logits)). Qubic had 1,404 wallets drained in October 2026 through a seed-generation weakness reported back in February ([BlockSec Phalcon](https://x.com/Phalcon_xyz/status/2112059239829242142)).

The market argues against a new token just as clearly. The US CLARITY Act failed Senate cloture 49–50 on 2026-09-15, and Sen. Lummis declared the bill dead, so token classification remains unsettled ([DLA Piper](https://www.dlapiper.com/en/insights/publications/2026/09/senate-fails-to-advance-the-clarity-act)). Gensyn launched an OP-Stack L2 and the $AI token in April 2026 but makes its money from the Delphi prediction market, and its training network is paused ([Gensyn testnet docs](https://docs.gensyn.ai/testnet); [hoge.gg](https://hoge.gg/de/gensyn-2026-delphi-ki-training-pausiert/)). The token sits around $0.019 ([cryptoticker](https://cryptoticker.io/en/prediction/gensyn-price-prediction/)), and compute tokens such as AKT and IO trade 90–98% below their highs ([hoge.gg](https://hoge.gg/akash-vs-io-net-render-depin-gpu-race-2026/)). A Bittensor subnet would bring ready-made miners and emissions, but registration cost about 225–435 TAO in late October 2026 and has spiked past 1,500 ([ownyourmind](https://ownyourmind.ai/projects/bittensor/); [CryptoBriefing](https://cryptobriefing.com/bittensor-subnet-registration-cost-rises/)). The Templar story also shows how fragile subnet teams and their governance can be.

The steelman for keeping training-as-consensus is that D-PoDL's pre-hash/post-hash binding is one of the few published answers to the SoK's reuse objection. Work bound to a specific chain head cannot be reused across blocks. That argument holds only if verification is real, which brings the analysis back to the previous two sections. The defensible position is a hybrid. Let an existing L2 or PoS chain provide consensus. Use D-PoDL's hash binding as a utility-aware difficulty and anti-precomputation device. Pay for training as validator-scored useful work, which is the "partial incentive allocation" the SoK recommends.

That points to a clear strategic niche. Bittensor subnets own practical training incentives. Gensyn owns verification-as-product. Prime Intellect owns the RL tooling. Nobody owns **the open, formally argued, end-to-end reference implementation of verifiable useful-work training.** Such an implementation would have a stated threat model covering grinding, reuse, plagiarism, PoL spoofing and publisher collusion, a security-budget analysis that answers the SoK, and working adversarial tests. Its flagship task should be a **verifiable autoresearch market**: frozen recipe, frozen multi-seed verifier, diffs from humans or agents, royalties along the lineage graph, disputes settled by bisection. The niche suits a time-limited owner because its value is credibility, not throughput. It can launch as a testnet on Base Sepolia or Arbitrum Sepolia with a valueless token. Its contracts can stay compatible with an EigenLayer-style AVS for later; EigenLayer slashing has been live since 2025-04-17 ([EigenLabs](https://www.eigenlabs.org/blog/slashing-goes-live/)). It can later be deployed as a subnet if traction justifies the TAO burn. A secondary track, RL rollout mining with toploc, verifiers and the Stoa worker pattern, has the lowest hardware barrier and can reuse the same contracts.

The phased plan assumes an owner with roughly 8–10 hours a week and leans on coding agents for migrations. The durations are this report's estimates, not sourced figures.

| Phase | Part-time duration | Deliverables | Exit criterion |
|---|---|---|---|
| **0. Stabilize and be honest** | 1–2 weeks | Fix the lockfile; scope CI to `pytest tests` plus `npx hardhat test`; freeze the current code on a `legacy-v0` branch; commit the review's attack PoCs (free mint, overflow halt, MTX brick, step cap, fabricated proof, manifest swap) as regression tests; rewrite the README status section | CI green; every PoC exists as a test the new design must make fail |
| **1. Validator-measured work** | 4–6 weeks | One task: a small modded-nanogpt/nanochat target ("reach val loss X in the fewest steps"); a frozen `train.py`/`verify.py` with k fixed seeds, ported from Prime Intellect's harness; miners submit a diff + commitment; a validator re-runs on a pinned GPU and container; `TaskEscrow` + `Submission` + simple settle on Base Sepolia; HF Bucket + CID storage; HtoA cut down to beacon seeds | A zero-work or self-reported submission cannot earn; an honest improvement settles end to end on 2–4 rented GPUs |
| **2. Disputes, lineage and anti-gaming** | 6–8 weeks | Stake and a challenge window; per-k-step checkpoint roots on chain; N-ary bisection to one step; a referee committee replaying on a pinned stack (Srivastava rounding logs for small models); lineage royalties for included diffs; Gauntlet assigned-vs-random anti-copy test; secret rolling eval set with commit-reveal | Red-team on about 16 rented RTX 5090s (about $200/day); Fang-style PoL spoofing, copying and grinding all fail or lose money |
| **3. Publish and pick one scale track** | Ongoing | Paper and threat model answering the SoK; then one of three: (a) collaborative DiLoCo/SparseLoCo training with Gauntlet scoring via torchft; (b) RL rollout mining with toploc + verifiers; (c) a subnet or AVS deployment. Swap in OVIG once code exists to admit heterogeneous GPUs | External miners or agents produce verified records; or a citable publication |

If time runs short, the minimum worthwhile revival is Phases 0 and 1 plus a public write-up. That alone would be the only open D-PoDL-lineage codebase where an untrusted submission is measured by someone other than its author. The project should not launch a mainnet token, chase zkDL-style training proofs, build its own P2P transport, keep Ray as the coordination layer, or require TEEs from miners. Two kill criteria are worth setting in advance. First, if pinned-stack replay cannot reproduce a training step bit-for-bit, or within a calibrated tolerance, on two different rented GPUs by the end of Phase 2, the dispute layer should fall back to Gauntlet-only scoring with stake. Second, if no outside miner or agent submits a verified improvement within two months of the testnet opening, the project should take the publishable research artifact and stop.

## Conclusion

The striking result of this review is that the 2026 systems and D-PoDL are each missing the other's half. Covenant's Gauntlet scores the usefulness of updates but commits to nothing about how they were produced. Verde commits to the full computation path but ships no incentive layer and cannot referee on chain. Prime Intellect's frozen verifier is cheat-resistant but has no market attached. D-PoDL's lasting contributions are the binding of work to chain state and a lineage graph that pays the models a result built on. Those are exactly the glue none of the three has. Revived around validator re-measurement and optimistic disputes, the paper's ideas turn from an unverifiable consensus claim into the incentive-and-provenance layer the decentralized-training field still lacks.

The second shift is in who the miners are. Frontier coding agents already close most of the gap to human speedrun records under frozen verifiers, so a useful-work network built in 2027 will increasingly be paying AI agents for research diffs. Its real consensus surface is the verifier, not the hash. A small team cannot win on compute or token liquidity, but it can be first to publish a rigorous, adversarially tested protocol for paying untrusted agents and humans for verified training improvements. Because well-funded competitors have pulled back from public training networks, this is the moment to claim that position.
